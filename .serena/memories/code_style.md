# Code Style & Conventions

## Language
- **Lua 5.1** — no Lua 5.2+ syntax (no `goto`, no integer/float split, no `//` operator). Code must run under both stock Lua 5.1 and LuaJIT.

## File / module layout
- **`src/Classes/`** — UI controls and tabs (`*Control.lua`, `*Tab.lua`) and core domain objects (`Item.lua`, `ModDB.lua`, `PassiveSpec.lua`, ...). One class per file, filename matches the class.
- **`src/Modules/`** — non-class subsystems (`Build.lua`, `CalcOffence.lua`, `CalcDefence.lua`, `ModParser.lua`, `StatDescriber.lua`, ...). PascalCase filenames.
- **`src/Data/`** — pure data tables. Many are auto-generated; respect the `-- This file is automatically generated, do not edit!` header.
- **`src/Export/`** — scripts that regenerate files in `src/Data/`.
- **`spec/System/Test*_spec.lua`** — busted specs; one per subsystem.

## Naming
- **PascalCase** for filenames, classes, and module tables.
- **camelCase** for functions and local variables.
- **UPPER_SNAKE_CASE** for constants where used.
- Class instance methods declared with `function ClassName:method(...)`.

## Modifier / mod system
- Modifiers flow through `ModDB`, `ModList`, `ModStore`, and `ModParser`. When adding new mod syntax, update `src/Modules/ModParser.lua` and the relevant data tables, then regenerate `src/Data/ModCache.lua` (Ctrl+F5 in a running PoB).
- Supported modifiers display in blue in-app; unsupported in red — keep that contract in mind when adding parsing.

## Debug aids
- `ConPrintf(...)` for console output. Search for `===` to find existing debug markers when cleaning up.

## Testing
- Tests must run headless via `HeadlessWrapper.lua`. Don't introduce hard SimpleGraphic dependencies in pure-logic modules.

## Documentation
- Project-internal docs in `docs/` (`addingMods.md`, `addingSkills.md`, `calcOffence.md`, `modSyntax.md`, `rundown.md`) — read these before touching the corresponding subsystems.
